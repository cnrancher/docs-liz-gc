无论您需要的是站点可靠性工程师 (SRE) 的意见，还是 Rancher 与 Kubernetes 专家的帮助，{short-project-name} 都能提供有效参考，帮助您更快做出正确决策。{short-project-name} 的优势在于：不仅支持与 Rancher UI 集成，也支持不依赖 Rancher 的独立 UI，并具备适应企业安全要求的多种能力。


== 关键组件

* **AI 智能体**: LLM 推理引擎与 MCP 服务（Rancher MCP 与 Kubernetes MCP）之间的领域专用桥梁。
  它将复杂请求分解并路由到安全的工具调用，同时强制执行安全防护措施。
  它确保上下文感知的执行，并将难懂的技术数据转化为清晰易懂的响应。
  它还提供统一的技术框架，同时支持独立 UI 和 Rancher UI 扩展。
* **Rancher MCP 服务**: 该组件依赖于 Rancher，适用于使用 Rancher 的场景。它是负责与 Rancher API 交互的 Rancher 模型上下文协议 (MCP) 组件，通过 Rancher 公共 API 机制，并以多种定制工具对外提供能力，从而带来最佳用户体验。
* **Rancher UI 扩展**: 该组件依赖于 Rancher，适用于使用 Rancher 的场景。它扩展 Rancher UI 以支持 {short-project-name}，不再局限于普通聊天窗口，而是将 {short-project-name} 嵌入 Rancher UI 的合适位置，并把助手集成到错误消息和状态徽章中，以提供即时的上下文支持。
* **Kubernetes MCP 服务**: 该组件不依赖于 Rancher，适用于无法使用 Rancher 的场景。它是负责与 Kubernetes API 交互的 Kubernetes 模型上下文协议 (MCP) 组件，通过 Kubernetes 公共 API 机制，并参考 kubectl 能力实现了多种定制工具对外提供能力，从而带来最佳用户体验。
* **独立 UI 支持**: 该组件不依赖于 Rancher，适用于无法使用 Rancher 的场景。它不仅提供与 Rancher 高度相似的权限管理能力，还提供以 kubeconfig 为核心的多集群管理能力，让未使用 Rancher 的用户也能友好地使用 {short-project-name}。

== 为什么需要 AI 助手？

随着 Kubernetes 环境规模的扩大，运维人员的“认知负担”呈指数级增长。{short-project-name} 旨在解决现代平台运维中的三个关键挑战：

. **缩小技能差距**：Kubernetes 的学习曲线向来陡峭。{short-project-name} 为不熟悉特定资源或错误类型的工程师提供即时的专家级支持，从而减少对资深“英雄”工程师的依赖。
. **加速解决问题**：运维人员无需再手动检查日志或搜索外部文档，即可请 {short-project-name} 总结命名空间的状态或解释特定故障，从而缩短平均故障解决时间 (MTTR)。
. **主动系统意识**：{short-project-name} 支持主动运维。通过询问“哪些部署当前处于不健康状态？”或“总结此集群的运行状况”等问题，团队可以在问题升级为故障之前识别并修复，从而实现主动系统感知。
