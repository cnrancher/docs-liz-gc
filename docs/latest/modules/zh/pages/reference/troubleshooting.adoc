== 快速故障排查

AI 助手位于 local 集群的 kopilot-system 命名空间中。您可以通过查看 Agent 日志，排查并定位相关问题。

[source,bash]
----
kubectl get po -n kopilot-system
----

如需获取 kopilot-agent pod 内 `kopilot-runtime` 容器的日志，请执行以下命令：
[source,bash]
----
kubectl logs -n kopilot-system -l app=kopilot-agent -c kopilot-runtime
----

如需获取 rancher-ai-mcp pod 的日志，请执行以下命令：
[source,bash]
----
kubectl logs -n kopilot-system -l app=rancher-mcp-server
----

== 启用 DEBUG 日志

Agent 包含 `operator`、`gateway` 和 `runtime` 三个容器，每个容器都可以单独开启 DEBUG 日志。

在 `values.yaml` 中，根据需要设置对应容器的 DEBUG 参数：

[source,yaml]
----
agent:
  operator:
    debug: true
  gateway:
    debug: true
  runtime:
    logLevel: DEBUG
----

其中：

* `agent.operator.debug`：开启 `operator` 容器的 DEBUG 日志。
* `agent.gateway.debug`：开启 `gateway` 容器的 DEBUG 日志。
* `agent.runtime.logLevel`：设置 `runtime` 容器的日志级别。

可以根据问题排查的需要，只开启特定容器的 DEBUG 日志，也可以同时开启三个容器的 DEBUG 日志。

然后，更新 Helm Chart:
[source,bash,subs="attributes+"]
----
helm upgrade --install \
    -n kopilot-system \
    --create-namespace \
    -f values.yaml \
    kopilot ./kopilot-{page-version}.tgz
----

== 在 Extensions 可用列表中看不到 SUSE AI Assistant GC

导入 Extension Catalog 后，返回 Extensions 页面，在可用列表中仍然看不到 `SUSE AI Assistant GC`。

您可以进入 Local 集群 -> Apps -> Repositories 页面，查看 `ui-extension-kopilot-ai-ui-charts` 的状态。

如果该 Repository 未处于 Active 状态，可点击下拉菜单中的 *Refresh*，等待 Repository 变为 Active。

image::quick-start/quick_start_4.png[Repositories 列表页面]

再次返回 Extensions 页面，即可看到 `SUSE AI Assistant GC` 插件。


== 更新模型配置

如果您通过 SUSE AI Assistant GC Settings 页面修改了模型配置，在执行 Helm upgrade 时需要将对应的模型配置同步到 `values.yaml` 中。

默认情况下，执行 Helm upgrade 时不会覆盖当前使用的模型配置，如果您希望使用 `values.yaml` 中的配置覆盖现有的模型配置，请将 `llm.forceUpdate` 设置为 `true`：

[,yaml]
----
llm:
  forceUpdate: true
----

== 使用 Ingress NGINX 时出现 `missing user header` 错误

在 RKE2 集群中，如果使用 ingress-nginx 作为 Ingress Controller，访问相关服务时可能出现以下错误：

[,text]
----
{ "type": "error", "links": {}, "code": "InvalidBodyContent", "message": "invalid request, missing user header", "status": 422 }
----

=== 原因

ingress-nginx 默认情况下会忽略包含下划线的请求头，导致服务端无法获取所需的用户信息，从而返回 `422` 错误。

=== 解决方法

在 `rke2-ingress-nginx-controller` ConfigMap 中启用下划线请求头支持：

[,bash]
----
kubectl patch configmap rke2-ingress-nginx-controller -n kube-system \
  --type merge \
  -p '{"data":{"enable-underscores-in-headers":"true"}}'
----

配置修改后会立即生效，无需重启 ingress-nginx Controller。

您可以使用以下命令确认配置是否已生效：

[,bash]
----
kubectl get configmap rke2-ingress-nginx-controller -n kube-system \
  -o jsonpath='{.data.enable-underscores-in-headers}'
----

预期输出：

[,text]
----
true
----

== 使用过程中页面自动退出登录

在使用 {short-project-name}^GC^ 的过程中，页面可能会自动退出登录，并出现以下错误：

[,text]
----
{"Code":{"Code": "Unauthorized", "Status": 401}, "Message": "must authenticate","Cause": null, "FieldName": ""}
----

=== 原因

如果 `values.yaml` 中缺少 `rancher_sso` 配置，Agent 无法正确获取或验证 Rancher 的认证信息，从而导致请求返回 `401 Unauthorized`，页面自动退出登录。

=== 解决方法

在 `values.yaml` 中配置 Rancher SSO：

[,yaml]
----
rancher_sso:
  enabled: true
  url: "https://rancher.mycompany.com"
----

将 `url` 设置为 Rancher Server 的实际访问地址。

修改 `values.yaml` 后重新执行 Helm upgrade，使配置生效。

== 访问 {short-project-name}^GC^ UI 重定向次数过多，无法访问

使用外部负载均衡器上终止 TLS 的方式部署 {short-project-name}^GC^，访问其 UI 时出现了重定向次数过多，无法进入页面的问题。

=== 原因

{short-project-name}^GC^ 所在集群的 ingress 控制器未启用与外部 TLS 的转发头机制。如果不设置此选项，外部 LB 将不断响应来自入口控制器的重定向请求。

=== 解决方法

集群中的 ingress 控制器开启 forwarded header 选项。

==== Ingress Nginx

[,yaml]
----
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: rke2-ingress-nginx
  namespace: kube-system
spec:
  valuesContent: |-
    controller:
      config:
        use-forwarded-headers: "true"
----

==== Traefik

[,yaml]
----
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: traefik
  namespace: kube-system
spec:
  valuesContent: |-
    additionalArguments:
      - "--entryPoints.web.proxyProtocol.insecure"
      - "--entryPoints.web.forwardedHeaders.insecure"
----

== Rancher MCP Server 启动异常

使用 {short-project-name}^GC^ 调用工具时，出现以下错误：

[,text]
----
host must be a URL or a host:port pair: "/k8s/clusters/local"
----

=== 原因

Rancher MCP Server 启动时需要读取 Rancher 的 `/v3/settings/internal-server-url` 配置。如果 Rancher 尚未完全就绪，可能无法获取正确的 Server URL，导致后续请求异常。

=== 解决方法

重新部署 Rancher MCP Server，然后重试 {short-project-name}^GC^ 工具调用，确认问题是否解决。

[,bash]
----
kubectl rollout restart deployment/rancher-mcp-server -n kopilot-system

kubectl rollout status deployment/rancher-mcp-server -n kopilot-system
----

[NOTE]
====
建议在 Rancher 完全就绪后再安装 {short-project-name}^GC^，避免 Rancher MCP Server 初始化时无法获取正确的 `internal-server-url`。
====

== 自建 OpenAI 服务连接失败（SSL 证书验证错误）

使用自建 OpenAI-compatible HTTPS 服务，且服务端使用私有 CA 或自签名证书时，{short-project-name}^GC^ 调用模型接口可能出现以下错误：

[,text]
----
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate
----

=== 原因

{short-project-name}^GC^ 无法验证自建 OpenAI 服务端的 TLS 证书，通常是因为服务端证书由私有 CA 签发，且该 CA 证书不在客户端默认信任链中。

=== 解决方法

将签发服务端证书的 CA 证书配置到 {short-project-name}^GC^ 的 `openaiCaSecret` 中，使其能够验证服务端证书。

. 创建包含 CA 证书的 Kubernetes Secret：
+
[,bash]
----
kubectl create secret generic openai-custom-ca \
  -n kopilot-system \
  --from-file=ca.crt=./ca.crt
----

. 在 {short-project-name}^GC^ Helm Values 中配置：
+
[,yaml]
----
llm:
  openaiCaSecret:
    name: "openai-custom-ca"
    key: ca.crt
----

[NOTE]
====
覆盖现有的模型配置，请将 `llm.forceUpdate` 设置为 `true`。

重新调用 OpenAI-compatible 接口，确认 SSL 证书验证错误已解决。
====

== OAuth2 身份认证无法自动获取 Metadata Endpoint

例如配置 Github Agent，输入正确的 MCP Endpoint（`\https://api.githubcopilot.com/mcp`），选择 `OAuth2 authentication`。但是 Metadata Endpoint 自动获取失败。

image::how-tos/mcp-oauth2-metadata.png[获取 Metadata Endpoint]

. 请检查 kopilot-system 下所有组件是否正常运行。
. 请确认 Rancher 是否为可信证书，如果不是，需要在 values.yaml 中额外设置：
+
[source,bash]
----
extraEnv:
  # Enable when Rancher uses an untrusted certificate.
  - name: KOPILOT_RANCHER_SKIP_TLS
    value: "true"
----

== 点击 Rancher UI 最左侧全局菜单，导致会话详情页面重新加载

在 Rancher v2.13.6 之前版本，打开 SUSE AI Assistant GC 会话详情页面后，切换最左侧全局菜单时（不同集群页面之间切换除外），会导致会话详情页面重新加载。

image::reference/rancher-ui-reload-chat-session.png[Rancher]

=== 原因

切换最左侧全局菜单时，导致页面布局变更，AI Assistant 窗口被销毁，并重新初始化，导致会话详情页面重新加载。
这个问题在 Rancher v2.13.6 版本中，由上游开源版本 UI 修复， 这里是对应的 https://github.com/rancher/dashboard/issues/15848[issue] 和 https://github.com/rancher/dashboard/pull/17371[PR]

=== 解决方法

升级 Rancher 版本到 v2.13.6 或更高版本。
